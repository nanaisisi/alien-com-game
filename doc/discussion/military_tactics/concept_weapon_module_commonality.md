# 兵器・モジュール共通化と運用経験値システム

本作（4X大戦略＋サブタイル戦術・戦闘団制）における兵器調達（独自開発・共同開発・ライセンス生産・輸入）、モジュール共通性（共通・類似）、および多層的な運用・実戦経験値エコシステムの仕様・設計検討ドキュメント。

---

## 1. 基本理念と設計方針

1. **「カタログスペック」と「現場の運用性」の乖離を表現**:
   - 単に新兵器を開発して即座に無敵になるのではなく、実戦投入初期のトラブル、運用時間・配備数による成熟、部品の共通化による補給の軽快さといった現実の防衛工学・軍事兵站の力学をゲームシステムとして組み込む。
2. **マイクロマネジメントの排除とシステム的還元**:
   - プレイヤーにネジや細かいボルトの型番を手動指定させるのではなく、「調達方式（独自・共同・ライセンス・輸入）」と「共通化ドクトリン」を選択させることで、戦闘団の整備性、稼働率、改修速度として自動的に還元する。
3. **外交・産業・軍種の多層的な連動**:
   - 外交協定（ライセンス・共同開発・輸入）が兵器のサプライチェーンと直結し、開戦時のパーツ枯渇リスクを生む。
   - 陸・海・空の軍種間をまたぐ共通モジュールの採用が、経験値蓄積のシナジーを生み出す。

---

## 2. 兵器調達の4形態

兵器および中核モジュールの調達方法は、4つの形態に分類される。

```text
+-------------------------------------------------------------------------+
| [自国独自開発] ─── [共同開発 (A国×B国)] ─── [ライセンス生産] ─── [完成品輸入] |
| (高コスト/高自由度)   (コスト折半/相互依存)    (国内生産/一部依存)    (即戦力/制裁リスク) |
+-------------------------------------------------------------------------+
```

| 調達形態 | 初期開発コスト | 量産コスト | 改修自由度 | サプライチェーン依存度 | 特徴と戦略的リスク |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **自国独自開発** | 極めて高 | 中 | 完全自由 | 依存ゼロ（完全自給） | 基礎産業基盤（Layer 1）と独自技術が必要。外交断絶に強い。 |
| **共同開発** | 低〜中（分担） | 中〜低（量産効果） | 要合意 | 参加国間に相互依存 | 相手国の得意モジュールを統合可能。外交関係悪化で開発遅延・中止リスク。 |
| **ライセンス生産** | 権利料のみ | 中＋ロイヤリティ | 軽度（国内仕様） | 基幹部品供給に一部依存 | プラットフォームは他国設計だが国内工場で組立。自国モジュール換装（魔改造）余地あり。 |
| **完成品輸入** | 開発費ゼロ | 高（外貨/資源流出） | なし（ブラックボックス） | 100%相手国依存 | 即座に戦力化。相手国と開戦・経済制裁を受けると**「部品枯渇による稼働率急落」**。 |

## 2.1 国内産業の自動化とプレイヤーの役割（ステアリング）

プレイヤーは「戦車のボルトを1本ずつ締めたり、師団内の装甲車を1台ずつ手動発注する」現場技師ではない。

- **編成自体の固定性**:
  - 戦闘団（師団）は「歩兵小隊・戦車小隊・砲兵支援班・工兵小隊」などの固定編成スロットで管理され、プレイヤーの現場操作負荷を極小化する。
- **国内産業の自動更新（自律的サプライチェーン）**:
  - 各国家は初期状態で自国の工業基盤・重工企業に応じた標準装備を自動生産し、固定編成スロットへ自動補給・配備している。
- **プレイヤーの立ち位置（国家指導者のドクトリン介入）**:
  - プレイヤーは基本的にニュートラルな国家システムの上に立ち、「全軍の共通化ドクトリン」「特定国とのライセンス協定」「重工から新興テックへの投資シフト」といった大戦略的方針（ドクトリン）を策定する。
  - この決定に基づき、国内産業の自動化ルーチンが徐々に更新され、部隊に配備される車両・モジュールの共通化率が自動的に最適化されていく。

## 3. モジュール共通性（Commonality）の階層

戦闘団（小部隊の集合体）や軍全体で使われるモジュールは、互換性の度合いによって分類される。

### 3.1 共通モジュール (Common Module, 共通性 100%)

- **定義**: 同一規格マウント、同一コネクタ、同一サプライチェーンを持つ部品（例: 同一規格の装輪走行系、共通RWS、共通タービンエンジン）。
- **ゲーム的効果**:
  - **部隊内共通化率（Commonality Index）の向上**: 戦闘団内の補給物資（消耗部品・予備品）の種類が減少し、整備小隊の修理速度向上、損耗補充コスト低減。
  - **生産ラインの統合**: 工業コンビナート（サブタイル）において、戦車・歩兵戦闘車・自走砲が同一モジュール生産ラインを共用可能（ライン切替コストゼロ）。
  - **経験値の完全共有**: どの兵種が運用しても、該当モジュールの経験値は100%加算される。

### 3.2 類似モジュール (Similar / Derivative Module, 共通性 30〜70%)

- **定義**: 同一設計思想や基本設計からの派生（例: 世代違いMk.1とMk.2、ライセンス先でのメートル法換算品、同口径だが砲身長や装填機構違い）。
- **ゲーム的効果**:
  - **部分的な整備互換**: 一部の消耗品や治具を共用可能（中程度の整備ボーナス）。
  - **経験値・改良ノウハウの部分波及**: 得られた経験値の一定割合（30〜70%）が派生・類似モジュールにフィードバックされる。

### 3.3 独自・専用モジュール (Proprietary Module, 共通性 0%)

- **定義**: 特定兵器専用に特化設計されたワンオフ部品（例: 試作超重戦車の専用動力炉、極超音速迎撃機の専用ステルス塗膜）。
- **ゲーム的な効果**:
  - 最高の単体性能・特化性能を発揮するが、予備部品の互換性がなく、損耗時の修理コスト・補給負荷が極めて重い。

## 4. 共通性向上のための管理情報・パラメータ定義

モジュールを異なる兵器間で共通化・標準化するためには、抽象的なカテゴリだけでなく、**「規格パラメータ（管理情報）」**を定義して整合性を判定する。

### 4.1 エンジン・動力モジュール：出力数（Power Output Rating）の規格化

エンジンや動力炉の共通化を判定・管理する中核パラメータは**「定格出力数（kW / MW、または出力クラス帯）」**とする。

- **出力クラス帯（Tier / Output Bracket）の管理**:
  - **超小型・補機級 (100〜300 kW)**: 軽装甲車、小型無人偵察車、移動式発電ユニット。
  - **中型級 (800〜1,200 kW)**: 歩兵戦闘車（IFV）、自走対空砲、装輪装甲車。
  - **大型・重工級 (1,500〜2,000 kW)**: 主力戦車（MBT）、重自走榴弾砲、沿岸高速哨戒艇。
  - **超大型・艦艇/航空級 (5,000 kW〜数十MW)**: 揚陸艦、大型輸送機、基地定置型シールド動力炉。
- **ゲームシステム上の共通化ルール**:
  - **同一出力数・同クラス**: ボルトオン換装可能（共通性 100%）。部品・フィルタ・伝達系（トランスミッション）の規格が共通化。
  - **出力差の派生（同一ブロック）**: ボアアップや過給機増設による出力違い（例: 1,200kW版と1,500kW版）は「類似モジュール（共通性 60%）」として扱い、コアブロックの部品や整備治具を共用可能。

### 4.2 アンテナアレイ素子・電波統合モジュール：多機能統合（戦闘機）vs 機能分担（艦船・基地）

フェーズドアレイレーダー（AESA）や通信アンテナにおける共通性は、**「アレイ素子（T/Rモジュール）単位の共通性」**に加え、プラットフォームによる**「統合アーキテクチャ（多機能一体型 vs 専用装置分散型）」**の違いを管理する。

- **戦闘機用AESA（高度多機能統合型 / Multi-Function RF System）**:
  - **極限の容積・重量制約による多目的化**:
    - 機首（レドーム）に複数の大型アンテナを載せるスペースがないため、単一のアレイ面で**「火器管制レーダー（FCS）」「電子攻撃（ECM / ジャミング）」「電子支援・電波逆探知（ESM）」「指向性高速データリンク（通信）」**を時分割・ビーム合成で同時にこなす極めて複雑な統合制御が求められる。
    - 物理的制約: ノーズコーン径（素子数上限）、機上発電限界、高密度排熱（液冷パッケージ）。
  - **ゲームシステム上の位置づけ**:
    - **高度統合モジュール**: 部品単価・ソフトウェア要求が極めて高い。
    - **電子戦・通信ドクトリンとの連動**: 改修や経験値によってレーダーだけでなくECM妨害力や部隊間データリンク通信速度も一括で向上する。
- **艦船・地上基地用アレイ（機能分担・専用分散型 / Distributed Dedicated Arrays）**:
  - **物理的余裕による要素分担（特化型アンテナの複数配置）**:
    - 容積・電力・冷却に余裕があるため、戦闘機のように単一アレイにすべてを詰め込む必要がなく、役割ごとに最適な専用装置を分担配置する。
      - 広域対空捜索レーダー（L/Sバンド・大型長距離特化面）
      - 個艦射撃指揮装置（Xバンド/ミリ波・高精度追尾特化イルミネーター）
      - 専用ECM妨害アンテナ / ESMアンテナ（マスト周囲への分散配置）
      - 艦隊・衛星間通信アンテナ
  - **サイズの自由度**: 素子数を数千〜数万個単位でスケール可能。
- **共通化ルールと波及構造**:
  - **素子半導体マテリアル世代（GaAs → GaN → ダイヤモンド素子）**:
    - **GaAs（ガリウム砒素）**: 第1世代。低出力・熱に弱く、稼働率・冷却負荷が大きい。
    - **GaN（窒化ガリウム）**: 現代標準（第2世代）。高出力・小型化が可能で、陸空海共通化のベースライン。
    - **ダイヤモンド半導体素子（究極のパワー半導体 / 第3世代・研究開発枠）**:
      - **特性**: 圧倒的な熱伝導率（GaNの数倍〜十倍以上）、超高耐圧・超高周波耐性。
      - **戦闘機での革命的ブレークスルー**: 戦闘機の最大の制約だった「機内排熱・冷却ポッドの容積限界」を打破し、小型レドーム内でも**超高出力パルス・超大出力ECM**を連続照射可能にする。
      - **宇宙・高放射線環境適応**: エイリアン環境や宇宙空間の高放射線・超極限温度にも耐える。
  - **半導体・素子レベル（Layer 1）の共通化**:
    - 同一素子マテリアル（GaNやダイヤモンド）の規格チップを共通調達することで、プラットフォームを超えた量産スケールメリットを獲得。
  - **機能・経験値の波及（クロス・フィードバック）**:
    - **戦闘機 → 艦船**: 戦闘機が実戦で培った「過酷な電波環境下でのECM/ESM電波妨害解析・波形制御アルゴリズム」が、艦船の専用ECM装置や電子戦ライブラリに還元される。
    - **艦船 → 戦闘機**: 艦船の大出力射撃指揮装置が蓄積した「超高精度目標追尾・クラッター除去アルゴリズム」が、戦闘機のFCS追尾精度向上にフィードバックされる。

## 5. 運用経験値の多層蓄積モデル

兵器の性能向上や信頼性改善は、「単一ユニットのレベルアップ（兵士の練度）」とは別に、**「国家・軍全体の運用ノウハウ蓄積（産業・技術・ドクトリンへの還元）」**として多層的に計算される。

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│                         【多層経験値（Experience Pool）】                        │
│                                                                                  │
│   ① 兵器全体経験 (Doctrine / Frame Exp)      : 車体・プラットフォーム・運用ドクトリン │
│   ② モジュール別経験 (Subsystem Exp)         : 動力、FCS、主砲、装甲、AI等       │
│   ③ ドメイン適応経験 (Domain Exp)            : 陸 / 空 / 海 / 複合領域           │
│   ④ 実戦過酷度・ストレス (Combat Stress)      : 平時演習 vs 実戦環境              │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 5.1 経験値蓄積の計算式（概念モデル）

1ターン（または一定期間）に蓄積される経験値 $\Delta Exp$ は、以下の要素の積として算出される：

$$\Delta Exp = \text{配備数 (Fleet Size)} \times \text{過酷度係数 (Strain)} \times \text{実戦環境係数 (Combat Multiplier)} \times \text{時間減衰/成熟補正}$$

1. **生産・配備数 (Fleet Size)**:
   - 少数試作機（プロトタイプ）では得られる運用データが限定的。
   - 大量配備されるほど統計的な故障・運用データが集まり、加速度的に経験値が蓄積。
2. **経過時間と成熟度 (Time in Service / Maturity)**:
   - 配備直後は「初期不良（Teething Troubles）」が存在し、トラブル発生率が高い。
   - 配備期間が長くなるにつれてノウハウが蓄積し、「枯れた技術（高信頼性・低維持費）」へとシフトする。
3. **使用過酷度 (Operational Strain)**:
   - 駐屯地待機（低） ＜ 長距離悪路走破・砂塵環境・寒冷地演習（中） ＜ 整備限界を超えた連続作戦・補給制限下での運用（高）。
4. **実戦環境（平時演習 vs 実戦陸空海）**:
   - **平時配備・演習**: 稼働率維持、整備マニュアル標準化、平時燃費改善（係数: 1.0）。
   - **実戦（Combat）**: 被弾データの収集、極限負荷下でのモジュール損傷解析、対エイリアン酸性粘液耐性など、決定的な改良ポイント（係数: 3.0〜5.0）。

## 6. モジュール共通性 × ドメイン（陸・空・海）の波及構造

モジュールを共通化している場合、運用環境（陸・空・海）で得られた経験値が**他ドメインの兵器へ横断的にフィードバック**される。

### 6.1 ドメイン別の過酷度と獲得ノウハウ

| ドメイン | 主な環境ストレス | 蓄積される経験値・改修知見 | 共通モジュールへの還元先 |
| :--- | :--- | :--- | :--- |
| **陸 (Ground)** | 泥濘、砂塵、超重力、エイリアン酸液、悪路振動 | サスペンション耐久、吸排気フィルター、耐衝撃装甲 | 装甲車、自走砲、重防衛タレット |
| **空 (Air)** | 高G旋回、高高度極低温、希薄大気、大気摩擦熱 | エンジン推力重量比、ステルス耐熱塗膜、長距離FCS | 迎撃戦闘機、偵察無人機、対地攻撃機 |
| **海 (Naval)** | 塩害腐食、水圧、荒天動揺、水中音響残響 | 耐腐食処理、大出力冷却機構、ソナー/全周レーダー解析 | 哨戒艦、揚陸艦、水陸両用装甲車 |
| **実戦（Combat）** | 敵性エイリアン攻撃、被弾、電子戦妨害 | 装甲バイパス配線、耐熱・難燃材、フェイルセーフ機構 | **全軍の採用兵器全体の生残性向上** |

### 6.2 クロス・フィードバックの具体例

- **共通エンジンの陸海連携**:
  - 主力戦車が過酷な陸上泥濘戦で得た「吸気目詰まり防止」「高負荷冷却」のデータが、同系統エンジンを採用している沿岸哨戒艇の燃費向上・オーバーホール期間延長として還元される。
- **共通FCSの空陸連携**:
  - 防空戦闘機がエイリアン小型飛翔体との空中戦で得た「極小高速目標の追尾アルゴリズム」が、同一FCSを積む対空自走砲の命中率補正に即時反映される。

## 7. ゲームプレイにおける戦略的トレードオフ

1. **「枯れた旧式共通車体」 vs 「最新鋭の独自設計」**:
   - 最新鋭車体はカタログ性能が高いが、経験値ゼロ・初期不良あり・生産コスト高。
   - 数十年運用された旧式車体は、蓄積された経験値により「稼働率+30%、整備費半減、砂塵・泥濘ペナルティ無効」といった絶対的な信頼性を誇る。
2. **「統合参謀ドクトリン（軍種間の共通化）」の決定**:
   - 陸軍と海軍で別々のエンジン・FCSを開発すると経験値が分散し非効率。
   - 「全軍共通規格」を強制すると、特定用途への特化性能はやや落ちるが、軍全体の経験値蓄積速度と兵站効率が跳ね上がる。
3. **「輸入・ライセンスの依存リスク」**:
   - 他国の優れたモジュールを輸入・ライセンスすれば即座に戦力化できるが、相手国との関係悪化で部品供給が止まれば「戦力崩壊」を招く。自国でのリバースエンジニアリングや類似モジュール開発への移行判断が問われる。
