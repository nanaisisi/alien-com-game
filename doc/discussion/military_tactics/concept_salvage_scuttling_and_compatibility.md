# 鹵獲・遺棄処理と互換性フリクション設計仕様書 (Concept Salvage, Scuttling & Compatibility Friction)

本ドキュメントは、本作（4X大戦略＋サブタイル戦術・戦闘団制）における**「兵器の撃破・遺棄時の自爆・焼却処理」「極小のサルベージ価値（鉄量と技術残滓）」「部隊投降時の器材無力化」「国家・都市降伏時の人材統合の困難性」「言語・機構・規格の非互換性フリクション」**を体系化した設計仕様書である。

---

## 1. 基本設計理念：鹵獲に対する冷徹なリアリズム

多くのゲームでは「敵の兵器を倒せばそのまま奪って使える」「降伏させれば即座に自軍戦力になる」という都合の良いボーナス処理がなされがちである。
しかし本作では、以下の現実的軍事・工学的力学を徹底してシミュレートする：

1. **徹底した破壊・焼却（Scuttling）**:
   - 遺棄・放棄される兵器は、軍規と自動化プロトコル（テルミット焼夷信管、自己破壊シーケンス）により内部から焼き尽くされ、敵に渡る前にほぼ無力化される。
2. **得られる物質的リターンの極小性**:
   - 炎上・溶融した残骸から得られるものは、精錬し直す必要のある**「わずかな低純度スクラップ鉄量」**と、焼け残った装甲構造や内部配置から得られる**「わずかな技術残滓（知見）」**にとどまる。
3. **都市単体での人材再利用の不可能性**:
   - 都市を1つ占領した程度では、高度な兵器体系を支えるサプライチェーン、研究機関、設計思想、行政制度が寸断されているため、現地の技術者を即座に兵器開発や生産に転用することはできない。
   - 国家単位で併合・統合し、かつ制度・言語・規格の壁を乗り越えて初めて、極めて緩やかに人材・技術の吸収が可能となる（それでも同化には莫大な年月と摩擦を伴う）。
4. **多層的な互換性の壁（Compatibility Friction）**:
   - 機構（ネジ、口径、油圧、電圧）、電子（IFF、暗号、データリンク）、言語（計器、マニュアル、コード）の非互換性が、他国装備・技術の直接利用を徹底的に阻害する。

## 2. 兵器・モジュールの撃破・遺棄処理（残骸サルベージの実態）

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                           戦闘後の戦場サルベージ処理                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ 撃破・遺棄時:                                                               │
│   ・乗員脱出/AI機能停止時に自爆・焼却プロトコル点火                         │
│   ・テルミットによるFCS・主砲施条・機関部の溶融破壊                         │
│                                                                             │
│ 回収されるもの (Salvage Outcome):                                           │
│   ① わずかなスクラップ鉄量 (Scrap Metal):                                  │
│      - 投入資源の数%〜十数%程度。再精錬コストが必要                         │
│   ② わずかな技術残滓 (Technical Remnants):                                  │
│      - 高温で変形しつつも残った装甲積層構造、内部モジュール配置の知見       │
│      - 該当技術ツリーへの微小な研究ボーナス（数%）                          │
│   ③ 奇跡的な可動モジュール:                                                │
│      - EMP完全麻痺や急襲による奇跡（通常発生確率 < 1〜3%）                  │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 自爆・焼却プロトコル（Scuttling Protocol）

兵器が戦闘不能または包囲され放棄される際、敵軍への技術・機材流出を防ぐため以下の処理が行われる：

- **電子機器・暗号ROMの物理破砕および熱破壊**:
  - FCS（射撃管制装置）、通信機、IFF（敵味方識別）鍵は即座にゼロクリアおよびテルミット溶融。
- **主武装の無力化**:
  - 砲身内での信管炸裂による施条（ライフリング）破壊、給弾機構の歪曲。
- **装甲・動力部の焼却**:
  - 機密合金や動力炉内部の制御棒・配管の意図的破壊。

### 2.2 サルベージで得られる価値

戦闘後の掃討・回収部隊が戦場から得られるリターンは意図的に低く設定される：

1. **スクラップ金属（低純度再生資源）**:
   - 兵器の建造コストと比較して極めてわずかな鉄・軽合金の塊。
   - そのままでは使用できず、工業サブタイルの精錬所・再資源化施設で処理する必要がある。
2. **技術残滓（Technical Remnants / Reverse Engineering Fragments）**:
   - 「この敵国は耐熱複合装甲をどのような積層順で配置しているか」「限られた容積内に動力炉と変速機をどうレイアウトしているか」という**設計思想・構造配置のヒント**。
   - 自国の該当技術開発に対して、一時的な「研究ポイント＋数％」の微小ボーナスを与える。

## 3. ユニット・部隊の投降処理

### 3.1 投降時の器材無力化

兵士が白旗を上げて降伏する際、彼らは兵器を無傷で引き渡すことはない。

- **投降前の器材破壊**:
  - 軍規により、降伏直前に小火器の遊底を外し投棄、装甲車の操縦盤破壊、照準器のレンズ叩き割りが行われる。
- **ゲーム内の扱い**:
  - 敵戦闘団が降伏しても**「兵器ユニットがそのまま自軍のインベントリに入る」ことはない**。
  - 得られるのは「捕虜（POW）」と「無力化された残骸（前述の低価値サルベージ）」のみ。
- **捕虜の兵站負担**:
  - 国際法・倫理ドクトリンを遵守する国家では、捕虜の給食・医療・収容施設維持に補給物資（食料・薬品）が継続的に消費され、前線戦闘団の兵站に負荷を与える。

## 4. 都市陥落 vs 国家併合：人材再利用の現実

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                           人材・技術の接収と再利用                          │
├──────────────────────────────────────┬──────────────────────────────────────┤
│ 都市単体の占領 (Capture of a City)   │ 国家単位の併合 (Annexation of State) │
├──────────────────────────────────────┼──────────────────────────────────────┤
│ × 人材の再利用は【不可能】           │ △ 極めて長い年月とコストで【一部可能】│
│ ・サプライチェーンの完全分断         │ ・国家機関・大学・公的文書の完全接収 │
│ ・上下流の設計規格が不在             │ ・ただし言語・思想・制度の同化摩擦   │
│ ・住民・技術者のサボタージュ         │ ・自国規格への再教育・再製図が必須   │
│ ・治安維持と難民救護の重い負担       │ ・併合後も数十年単位で非効率が残存   │
└──────────────────────────────────────┴──────────────────────────────────────┘
```

### 4.1 なぜ都市単体の人材は再利用できないのか

1. **サプライチェーンの欠落**:
   - 現代・未来の高度兵器は、単一都市で完結して作られることはない。特殊レアメタル精錬都市、センサー半導体製造都市、ソフトウェア開発都市などがネットワーク化されて初めて成立する。
   - 1都市を切り取っても、前後工程が敵対国側に残っているため、現地の技術者がいても何も組み立てられない。
2. **設計図面と検証環境の不在**:
   - 機密図面サーバーは陥落直前に消去・暗号化される。現場の技術者の「頭の中の断片知識」だけでは、複合システムの再現は不可能。
3. **面従腹背とサボタージュ**:
   - 占領された都市の住民・技術者は強い敵愾心を持っており、強制労働させれば不良品の混入、意図的な設計遅延、情報漏洩を招く。

### 4.2 国家単位で取り込んだ場合のシビアな同化プロセス

国家全体を完全降伏させ、領土・制度・研究施設を包括的に接収（Annexation）した場合にのみ、人材資源の再利用が視野に入る。
しかし、それすらも自動的な獲得とは程遠く、以下の障壁が立ちはだかる：

- **知的財産の解読・再編成コスト**:
  - 接収した膨大な図面・特許・学術論文を、自国の標準規格・言語へ翻訳・翻案する専用の「統合プロジェクト（国家タスク）」が必要。
- **思想審査と忠誠度の確保**:
  - 敵国の主任設計者を自国の国防プロジェクト中枢に入れるには、厳しい身元調査と監視が必要であり、即座にフルパワーを発揮させることはできない。

## 5. 互換性の壁（Compatibility Friction Layer）

鹵獲した残骸、接収した設備、あるいは輸入兵器を自軍で運用・研究しようとする際、常に以下の**「4大非互換性」**がフリクション（摩擦・コスト増大）として発生する。

```text
               ┌─────────────────────────────────────────┐
               │         互換性の4重の障壁               │
               ├─────────────────────────────────────────┤
               │  [Layer 4] 制度・法体系・安全基準       │
               │  [Layer 3] 言語・UI・技術文書           │
               │  [Layer 2] 電子・暗号・IFF・通信        │
               │  [Layer 1] 機構・物理寸法・ボルト規格   │
               └─────────────────────────────────────────┘
```

| 階層 | 非互換性の具体例 | 自軍システムへの影響・ペナルティ |
| :--- | :--- | :--- |
| **① 機構・物理規格** (Mechanical) | ・ネジ規格（メートル法 vs ヤードポンド法、公差基準） / ・主砲口径・薬室形状（120mm vs 125mm） / ・動力の電圧・油圧基準、コネクタ形状 | 弾薬・補給部品が自軍サプライチェーンと一切共有できない。故障時に自前工場で部品が削り出せず、共食い整備（部品取り）しか維持手段がない。 |
| **② 電子・暗号・IFF** (Avionics & Network) | ・敵味方識別（IFF）応答プロトコル / ・戦術データリンクの変調方式・周波数帯 / ・火器管制・エッジAIの認証キー | 自軍の戦術C4Iネットワークに接続不能。レーダー上で「友軍」と自動認識されず、**友軍誤射（フレンドリーファイア）の極めて高いリスク**を負う。 |
| **③ 言語・インターフェース** (Language & UI) | ・操縦席の計器表示、HUD、音声警告の言語 / ・整備マニュアル、配線図、ソースコードの記述言語 / ・運用ドクトリンの用語体系 | 自軍兵士が直感的に操作できず、誤操作・事故率が激増。整備兵がマニュアル解読に時間を取られ、稼働率が著しく低下する。 |
| **④ 制度・度量衡・思想** (Doctrinal & Legal) | ・部品の耐用年数基準（使い捨て思想 vs 整備長寿命思想） / ・品質管理基準（公差の緩さ、歩留まりの許容度） | 接収工場で自国兵器を作らせようとしても、工作機械の精度や労働慣行の違いから不良品が多発する。 |

### 6.1 サルベージ・撃破処理モデル

```rust
use serde::{Deserialize, Serialize};

/// 戦場サルベージ処理の結果
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SalvageYield {
    /// 焼け残った低純度スクラップ金属量 (t)
    pub scrap_metal_tonnage: f32,

    /// 破壊を免れた断片的な工学知見
    pub technical_remnants: Vec<TechRemnant>,

    /// 奇跡的に原形を留めた希少モジュール (極めて稀: 通常0件)
    pub intact_modules: Vec<CapturedModule>,
}

/// 技術残滓（断片知見）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct TechRemnant {
    /// 対象技術カテゴリ (装甲工学、内部容積配置、推進技術など)
    pub tech_category_id: String,
    /// 研究ツリーへの一時的進捗ボーナス (例: 0.02 = +2.0%)
    pub insight_value: f32,
    /// 判明した敵国固有の設計特徴
    pub description: String,
}

/// 撃破・遺棄時のサルベージ計算
pub fn process_battlefield_salvage(
    original_tonnage: f32,
    scuttling_success: bool, // 乗員やAIによる自爆・焼却が成功したか
    is_emp_disabled: bool,   // EMP等の特殊無力化による完全麻痺か
) -> SalvageYield {
    if is_emp_disabled {
        // EMP奇襲等による特殊ケース（自爆失敗）：わずかに価値向上
        return SalvageYield {
            scrap_metal_tonnage: original_tonnage * 0.25,
            technical_remnants: vec![
                TechRemnant {
                    tech_category_id: "avionics_architecture".into(),
                    insight_value: 0.05,
                    description: "未破壊の電子基板からバス配置の知見を獲得".into(),
                }
            ],
            intact_modules: vec![],
        };
    }

    // 通常の撃破・遺棄：テルミット自爆・高熱溶融により壊滅的破壊
    let recovery_ratio = if scuttling_success { 0.05 } else { 0.12 };

    SalvageYield {
        scrap_metal_tonnage: original_tonnage * recovery_ratio,
        technical_remnants: vec![
            TechRemnant {
                tech_category_id: "armor_metallurgy".into(),
                insight_value: 0.015,
                description: "溶融した装甲残滓から複合装甲の積層比率を推測".into(),
            }
        ],
        intact_modules: vec![],
    }
}
```

### 6.2 互換性フリクション（Compatibility Friction）モデル

```rust
/// 鹵獲・接収品および他国設計に対する互換性評価プロファイル
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CompatibilityProfile {
    /// 機械・物理規格適合度 (0.0: 完全独自/ヤード等 ～ 1.0: 自国規格と完全一致)
    pub mechanical_compatibility: f32,

    /// 電子・IFF・データリンク適合度 (0.0: 孤立・誤認射撃リスク ～ 1.0: 完全リンク)
    pub electronics_compatibility: f32,

    /// 言語・マニュアル・UI適合度 (0.0: 未翻訳・難読 ～ 1.0: 完全ローカライズ)
    pub linguistic_compatibility: f32,
}

impl CompatibilityProfile {
    /// 整備負荷倍率 (規格が合わないほど部品調達・整備が困難)
    pub fn maintenance_load_multiplier(&self) -> f32 {
        // 互換性が低いと整備負荷は最大4.0倍に跳ね上がる
        1.0 + (1.0 - self.mechanical_compatibility) * 3.0
    }

    /// 戦闘時のフレンドリーファイア（友軍誤射）リスク確率
    pub fn friendly_fire_risk_rate(&self) -> f32 {
        if self.electronics_compatibility < 0.3 {
            // IFF未改修の場合、混戦時に友軍から敵と誤認される重大リスク
            0.15 * (1.0 - self.electronics_compatibility)
        } else {
            0.0
        }
    }

    /// 操縦・操作ミス発生率（計器・言語の非互換）
    pub fn operational_mishap_rate(&self) -> f32 {
        (1.0 - self.linguistic_compatibility) * 0.20
    }
}
```

### 6.3 国家併合 vs 人材統合コストモデル

```rust
/// 国家接収時の人材・知財統合タスク
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct IntegrationProject {
    pub annexed_faction_id: String,
    /// 翻訳・規格統一の進捗度 (0.0 〜 1.0)
    pub integration_progress: f32,
    /// 割り当てられた自国の研究者・官僚数
    pub assigned_bureaucrats: u32,
    /// 現地技術者の不服従・サボタージュ率 (治安と時間に反比例)
    pub sabotage_risk: f32,
}

impl IntegrationProject {
    /// 都市単位の占領では人材統合プロジェクト自体を【開始不可】とする判定
    pub fn can_integrate_human_capital(is_entire_nation_annexed: bool) -> bool {
        // 都市単体では上下流の産業基盤が分断されているため、人材の組織的活用は不可能
        is_entire_nation_annexed
    }

    /// 毎ターンの統合進捗処理
    pub fn tick_turn(&mut self, local_unrest: f32) {
        if self.integration_progress >= 1.0 {
            return;
        }

        // 治安悪化（Unrest）が高いほどサボタージュが発生し進捗が停滞
        self.sabotage_risk = (local_unrest * 0.7).clamp(0.0, 0.9);
        let effective_speed = (self.assigned_bureaucrats as f32 * 0.001) * (1.0 - self.sabotage_risk);
        
        self.integration_progress = (self.integration_progress + effective_speed).min(1.0);
    }
}
```

## 7. まとめとゲームプレイ体験への還元

1. **「鹵獲で一発逆転」の甘い幻想を排除**:
   - 撃破した敵の残骸を漁っても、手に入るのは少量のスクラップ鉄と、わずかな装甲積層構造のヒントのみ。
   - プレイヤーは「鹵獲兵器で戦力を賄う」という安易な戦略を取れず、自国の工業基盤とサプライチェーンを如何に維持するかに意識を集中させることになる。
2. **占領都市のリアルな重荷**:
   - 都市を落としても「即座に現地の優秀な技術者を徴用して新兵器を作らせる」ことはできず、むしろ補給路の断絶、治安維持コスト、規格の違いによる産業麻痺という現実の軍政の苦悩に直面する。
3. **他国兵器運用の高い代償**:
   - 仮に奇跡的に敵兵器を手に入れたり、輸入兵器に依存した場合でも、**「ボルト規格が合わない」「IFFが繋がらず友軍に撃たれる」「操縦席の計器言語が読めず事故る」**という互換性フリクションがプレイヤーの前に立ちはだかる。
