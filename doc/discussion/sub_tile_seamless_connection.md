# タイル内マップ・タイル間接続システム検討書

本ドキュメントは、全体マップ（マクロ大戦略層）とタイル内マップ（ミクロ局所運用層）をつなぐ**「タイル間接続のシームレス感」**に関する技術・ゲームデザインの課題と解決アプローチの整理、およびマクロ視点を意識したユニットシステム・サブタイルの検討保留事項をまとめたものです。

---

## 1. 課題認識：「タイル間接続のシームレス感」の難しさ

全体マップから単一タイルの詳細マップへ移行する際、以下のような断絶・不自然さが発生しやすい課題があります：

1. **空間・境界の断絶（孤立アリーナ化の罠）**:
   - サブタイルを単に「1ヘックスの内部」として切り離して画面遷移（ロード画面や暗転）してしまうと、周囲の戦況や地形の流れから孤立した「単なるミニバトル画面」になり、マクロ感・大戦略との繋がりが失われる。
2. **境界線（エッジ）の連続性**:
   - 親タイルの隣が「川」「海岸」「山岳」「道路」だった場合、サブマップの外周境界がその隣接地形と自然につながっていないと違和感が出る。
3. **隣接タイルからの影響（増援・射程・視界）の可視化**:
   - 隣のタイルにいる友軍の支援砲撃や増援、敵の包囲網が「サブマップの外」からどう入ってくるか、あるいは外側がどう見えているかの演出・ルール設計。
4. **カメラとスケール変形**:
   - カメラの無段階ズームイン／ズームアウトで違和感なくマクロとミクロの表示が切り替わるか。

## 1.1 幾何学的なジレンマ：同一配向タイリングと直線境界の相反

同じ互い違いヘクス（同一のPointy-topped配向）をそのまま小ヘックスとして敷き詰めようとした場合、以下の数学的・幾何学的な相反関係が発生します：

- **ヘックスは自己相似分割（レプ・タイル化）が不可能**:
  正方形や正三角形と異なり、ヘックスを同じ向きの小さなヘックスで隙間なく均等に分割することは数学的にできません。
- **直線の親境界 vs ギザギザの小ヘックス群**:
  小ヘックスの自然なタイリングを優先すると、親ヘックスとの境界線がジグザグのギザギザになり、横一列の大ヘックス同士の境界線（直線）と綺麗に一致しなくなります。逆に直線の親境界で無理やり切ると端の小ヘックスが欠損します。

## 1.2 回転階層ヘクス（Rotated Hexagonal Hierarchy / Aperture 3・7）の検討

この幾何学的ジレンマを解消・緩和するアプローチとして、GISや空間幾何学で標準的に用いられている「回転階層ヘクス」の手法が存在します。

### 代表的な体系とオンライン資料

1. **Aperture 3（30度回転ヘクス）**:
   - **原理**: 親ヘックス（Pointy-topped: 上が尖った六角形）を細分化する際、子ヘックスを **30度回転**（Flat-topped: 上が平らな六角形）させて敷き詰める手法（面積比 1:3）。
   - **特徴**: 子ヘックスの平らな辺が、親ヘックスの斜めの直線辺と**ピッタリ平行**になるため、境界線沿いのはみ出し・欠損が極小化され、幾何学的な収まりが美しい。
   - **学術参照**: Discrete Global Grid Systems (DGGS) における Kevin Sahr 氏の研究など。
2. **Aperture 7 / Uber H3（約19.1度回転）**:
   - **原理**: 親ヘックス1つの領域を7つの子ヘックス（中心1 + 周囲6）で近似する階層型空間インデックス。解像度を1段階深くするごとに **約19.108度** 回転する。
   - **オンラインドキュメント**:
     - [Uber H3: Hexagonal hierarchical spatial index](https://h3geo.org/docs/core-library/h3Indexing/)
     - [Wikipedia: Gosper curve (ゴスパー曲線・Gosper Island)](https://en.wikipedia.org/wiki/Gosper_curve)

### ゲーム視点でのトレードオフ

| 項目 | 通常の同一配向ヘクス | 30度回転ヘクス (Aperture 3) |
| :--- | :--- | :--- |
| **境界線の収まり** | 境界がギザギザになり親タイルの直線辺と相反する | 子の辺が親の辺と平行になり、境界の幾何学的整合性が高い |
| **移動・操作の直感性** | マクロ・ミクロで移動方向（6方向）が完全に一致 | **拡大時に操作軸が30度傾く**ため、操作感・視覚方向の混乱が生じやすい |
| **実装・座標系** | 既存の `HexCoord` がそのまま流用可能 | PointyとFlatで座標系変換（偶奇行ルール）が交互に入れ替わる |

## 2. タイル間接続をシームレスにする4つの設計アプローチ

### アプローチA:「窓（インスペクション・レンズ）型シームレス展開」【最有力】

全体マップの画面を切り替えるのではなく、**注目タイルがその場で展開（アンフォールド）され、周囲のタイルは背景としてそのまま見え続ける**方式。

```text
       [ 隣接: 山岳タイル ]
             ▲
   [隣接:森] │ [隣接:平原]
        ◄─── ┼ ───►
             │  (ターゲットタイル)
     ┌───────┴───────┐
     │  サブグリッド  │   ← 周囲の6隣接タイルは
     │   (局所戦術)  │      そのまま周囲に薄く表示・維持される
     └───────┬───────┘
        ◄─── ┼ ───►
  [隣接:川]  │ [隣接:自軍戦闘団]
             ▼
```

- **表現・構造**:
  - 対象タイルにカメラが寄ると、対象タイルだけがサブグリッド（小ヘックス群）にスムーズに変形・細分化（LOD遷移）。
  - **周囲の6つの大ヘックスはそのまま画面外周に存在**し、霞（フォグ）や少しフェードした状態で接続されている。
- **シームレス性のメリット**:
  - プレイヤーは「自分が広大な惑星のどの地点で戦っているか」の空間認識を一切失わない。
  - 東の隣接タイルに味方部隊がいれば、サブマップの東の境界線越しにその味方戦闘団のアイコンが実際に見える。

---

### アプローチB:「境界共有（アウター・フリンジ）型生成」

サブマップを生成する際、対象の1タイルだけでなく**隣接する6タイルの端（外周バッファ層）も含めてプロシージャル生成**する方式。

- **仕様**:
  - サブマップの中央部（アクティブエリア）が本来の親タイルの領域。
  - 外周1〜2小ヘックス分は、**隣接タイルの地形（山岳なら崖、川なら水流、森林なら木立）が境界を跨いで連続して配置**される「進入不可／退却用フリンジ領域」。
- **シームレス性のメリット**:
  - 親タイル同士の境界線で地形（川や道など）が途切れず、自然な地続きのランドスケープとして描画される。
  - 「退却」する際も、隣接タイルの方向にある外周フリンジへ部隊を移動させるだけで直感的に成立する。

---

### アプローチC:「マクロ・ミクロ同時重層型（Seamless Zoom / LOD）」

大戦略ゲーム（Supreme Commander や Planetary Annihilation）のような、**カメラ高度（Distance）に応じた完全連続スケール**。

- **仕様**:
  - 高高度カメラ: 大ヘックスグリッド、戦闘団アイコン、都市名、領土境界線を表示。
  - 中・低高度カメラ: 大ヘックスの境界が透過し、地形テクスチャの詳細とサブタイル・小部隊モデルがフェードイン。
- **課題と検討**:
  - 実装難易度・描画負荷が最も高い。
  - 全世界を同時にサブタイル化すると負荷が破綻するため、「交戦中または選択中のタイルのみLODで細分化メッシュをロードする」ハイブリッド方式が現実的。

---

### アプローチD:「周辺タイルからの干渉・オフマッププロジェクション」

隣接タイルの戦力や環境が、サブマップ内にどうシームレスに影響を及ぼすかのルール。

1. **オフマップ砲撃・航空支援**:
   - 隣接タイルに榴弾砲部隊や空母・航空団がいる場合、サブマップ内に直接ユニットとして入るのではなく、**「毎ターン1回、マップ外からの座標指定支援砲撃スキル」**としてUIに表示。
2. **増援の物理的進入**:
   - 地上部隊が隣接タイルから増援に来る場合、サブマップの該当する方角のエッジから2ターン目に移動して侵入。
3. **環境の浸透（瘴気・天候）**:
   - 風上や隣接タイルに「瘴気（Miasma）」や「毒性湿地」がある場合、その方角の境界からサブマップ内へ瘴気ガスが流れ込んでくる。

## 3. 保留・継続検討事項（マクロ視点を意識した整理）

以下の2点については、マクロ大戦略（4X）としてのゲームテンポ・操作量を損なわないバランスを見極めるため、基本方針をメモした上で**詳細設計・実装は保留**とします。

### 3.1 ユニットシステム（戦闘団 ⇔ 小部隊のバランス）

- **マクロ意識の原則**:
  - プレイヤーが全体マップで操作するのは常に「戦闘団（固定編成）」であり、個別の兵士や小隊を全体マップで1体ずつ動かす煩雑さ（Civ5/6の1UPT渋滞問題）は徹底して避ける。
- **保留論点**:
  - サブタイル展開時の小部隊の自律性（AIに任せる委任指揮 vs 完全手動指揮）。
  - 小部隊の損耗がマクロの戦闘団HP・戦力にどう還元されるか（例: 戦車小隊が全滅した場合、戦闘団の「装甲火力」ステータスが次回から欠損する等）。
  - 編成のカスタマイズ性（戦闘団内の小部隊スロットを都市で組み替える機能の是非）。

### 3.2 サブタイル（ミクロマップの規模・頻度・非戦闘利用）

- **マクロ意識の原則**:
  - 毎ターン何回もサブタイル戦が発生して大戦略が進まない「戦術戦疲れ」を防ぐ。
  - 原則はオートリゾルブ（自動解決）でサクサク進み、「勝負所・ボス戦・深層遺跡調査」でのみ手動サブタイルへ潜るメリハリ。
- **保留論点**:
  - サブタイルのヘックス規模（手軽な半径3: 37ヘックス vs じっくり半径4: 61ヘックス）。
  - 戦闘以外の活用（都市タイルの内部開発・区画配置、あるいはエイリアン巣窟のバイオリアクター設置など）。

## 4. 今後の検証・アプローチ計画

1. **フェーズ1（シームレス描画のPoC）**:
   - 画面遷移を挟まず、全体マップ上で選択した1ヘックスのメッシュをサブヘックス群に展開し、カメラを寄せるトランジションの試作。
   - 周囲6ヘックスの地形・アイコンを透過・背景表示したままにする描画テスト。
2. **フェーズ2（隣接境界接続テスト）**:
   - 川や道路が親タイルのエッジを跨いでサブマップ内に正しく伸びてくる接続生成ロジックの検証。
3. **フェーズ3（ユニット展開とマクロ還元）**:
   - 保留事項のユニットシステムと連携し、戦闘団から小部隊への展開・戦闘結果のマクロ反映を実装。
