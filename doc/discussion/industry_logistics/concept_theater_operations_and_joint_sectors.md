# 方面軍システムと自動指揮・共同管理領域設計仕様書

(Theaters of Operations, Automated Command Hierarchy, and Overlapping Joint Sectors)

本ドキュメントは、本作（4X大戦略＋サブタイル戦術・戦闘団制）において、多数の戦闘団・守備隊・治安部隊を破綻なく統率するための**「方面（Theater / Front）システム」**、**「軍集団・タスクフォースによる階層ツリー編制」**、**「単独専念領域と方面間共同管理領域（オーバラップ戦域）」**、および**「同盟統合軍の連携とエイリアン（集合意識方面集団）が複数国に包囲される力学」**を体系化した設計仕様書である。

---

## 1. 全体設計思想：なぜ「方面システム」が必要なのか

### 1.1 背景課題：ユニット数増大に伴うマイクロマネジメントの破綻

本作は「脱・都市中心」のタイル拡張モデルを採用しており、前線基地・資源採掘地・兵站中継点・占領地ごとに多数の戦闘団（師団相当）や守備隊、国境警備隊、憲兵隊が展開する。
プレイヤーが1ユニットずつ手動で「移動・攻撃・駐留・索敵・補給」を指示すると、中盤以降に**極度の操作負担（マイクロマネジメント地獄）**が発生する。

### 1.2 解決方針：階層ツリーと「境界管理」による自動化

プレイヤーは高位の「方面軍（Theater Command）」およびその下の「軍集団（Army Group）/タスクフォース」に対し、**作戦領域（Sectors）、作戦目標（Objectives）、ドクトリン（Stance）**を指定する。各級司令部AIが直下の戦闘団へ移動・陣形維持・補給要求・攻撃/後退を自動発令する。

さらに、方面間に**「共同管理領域（Joint Overlapping Sector）」**を定義することで：

1. **専念領域（Dedicated Sector）**: 担当軍集団が100%リソースを注ぎ込み、独自ドクトリンで徹底的に攻略・防衛する領域。
2. **共同管理領域（Joint / Overlapping Sector）**: 2つ以上の方面・軍集団が相互に情報・火力を共有し、共同で厚みのある防衛・侵攻・兵站補給を行う領域。

これにより、「正面作戦に専念しつつ、境界の隙間を共同で補い合う」有機的な戦線形成が可能となる。

```text
+-----------------------------------------------------------------------------------------+
| 【最高統帥部（プレイヤー）】                                                           |
|  - 方面軍の設置・管轄タイルの線引き・総司令官任命                                      |
|  - 方面間の共同管理領域（オーバラップゾーン）の指定                                    |
|  - 資源・弾薬・補充枠の大枠プライオリティ配分                                          |
+--------------------------------------------┬--------------------------------------------+
                                             │ ドクトリン・作戦目標・軍団配属
                                             ▼
+-----------------------------------------------------------------------------------------+
| 【方面軍司令部 (Theater HQ) / 軍集団 (Army Group)】                                     |
|  - 専念領域での侵攻・防衛・哨戒・占領統治の自動執行                                    |
|  - 共同管理領域における火力支援・相互増援・補給融通の調停                               |
|  - サブタイル戦術自動解決（Auto-Resolve）における陣形・砲兵支援の統制                   |
+-----------------------------------------------------------------------------------------+
```

## 2. 指揮統率の階層ツリー構造 (Hierarchy Tree)

方面軍は下位の作戦目的に応じて柔軟に分岐・細分化できるツリー構造をとる。

```text
最高統帥部 (Supreme High Command / プレイヤー)
│
├── 東部方面軍司令部 (Eastern Theater Command HQ)
│   │── [管轄領域]: 東部セクター全域 ＋ 南部方面との境界共同管理区
│   │── [方面ドクトリン]: 積極攻勢・インフラ接収重視
│   │
│   ├── 対A国 A侵攻軍集団 (Army Group "Spearhead" vs Nation A)
│   │   ├── 第1機甲打撃戦闘団
│   │   ├── 第2機甲打撃戦闘団
│   │   └── 重砲兵・ミサイル旅団 (長距離火力投射)
│   │
│   ├── 対A国 B侵攻軍集団 (Army Group "Hammer" vs Nation A)
│   │   ├── 第5諸兵科連合戦闘団
│   │   ├── 第6機械化歩兵戦闘団
│   │   └── 工兵・インフラ架橋連隊
│   │
│   ├── 対A国 D占領軍集団 (Army Group "Pacification" vs Nation A / 新規制圧地・治安軍政)
│   │   ├── 軍政・治安司令部 (Military Governorate HQ)
│   │   ├── 憲兵隊 (MP) / 独立特務捜査大隊 (地下反乱摘発・治安維持)
│   │   ├── 後方インフラ・兵站護衛連隊 (送電・パイプライン・弾薬デポ防護)
│   │   └── 現地自治警察・補助部隊 (Schutzmannschaft)
│   │
│   └── 対B国 E守備軍集団 (Army Group "Shield" vs Nation B / 従来国境軍事防衛)
│       │── [管轄領域]: B国国境要塞線・山脈地帯 (共同管理領域含む)
│       ├── 【通常機能（平時）】: 国境警備隊・税関検問隊 (密輸遮断・不法越境監視・情報収集)
│       ├── 【非常用防衛戦力】: 第3要塞歩兵戦闘団 / 第8重砲兵群 (本格侵攻への即応迎撃)
│       └── 要塞防空・電子警戒中隊
│
└── 南部方面軍司令部 (Southern Theater Command HQ)
    ├── 資源地帯確保タスクフォース
    └── 対エイリアン方面包囲軍集団
```

### 2.1 軍集団の特化役割（Role Profiles）

各軍集団には「作戦役割」を付与でき、司令部AIのアルゴリズムが切り替わる。

1. **侵攻突破軍集団（Assault / Spearhead: A・B侵攻軍集団等）**:
   - 敵の防衛線薄弱部を索敵・突破し、中枢・資源タイルへの進撃を最優先。
   - 損耗を恐れず高出力戦闘を維持。補給線が細くなると自動で一時進撃停止・再編を行う。
2. **新規制圧占領軍集団（Occupation & Military Governance: D占領軍集団等）**:
   - 侵攻軍が進撃・突破した後の「被占領地域（新領土）」における軍政・治安維持を担当。
   - [concept_occupation_governance_and_divided_economy.md](./concept_occupation_governance_and_divided_economy.md) で定義された憲兵隊・独立捜査機関・現地自治体警察を統率し、地下レジスタンスの摘発、協力者の保護、インフラ復旧を自律執行。侵攻戦闘団から治安維持の足止め負担を完全に切り離す。
3. **従来国境守備軍集団（Border Defense: E守備軍集団等）**:
   - 自国の既存国境や要衝山脈線を守る部隊。
   - **平時（通常機能）**: 主体は**国境警備隊（Border Guards）**が担い、密輸遮断・境界哨戒・スパイ侵入阻止を低維持費で定常的に実施。正規軍は「非常用」として後方予備・待機状態に置かれ、維持費を最小化。
   - **戦時（非常用防衛機能）**: 本格的な敵侵犯・宣戦布告に伴い、待機していた**正規軍事守備隊・要塞戦闘団**が即座に前線展開。要塞陣地・防空網・重砲台に拠って敵の攻勢を物理粉砕・拘束する。

## 3. 「専念領域」と「方面間共同管理領域」のメカニクス

本システムの中核概念である領域管理の仕様。

```text
 ┌───────────────────────┐                     ┌───────────────────────┐
 │   東部方面軍 専念領域   │                     │   南部方面軍 専念領域   │
 │   (Dedicated Sector)  │                     │   (Dedicated Sector)  │
 │                       │                     │                       │
 │ ・東部軍集団が単独指揮│                     │ ・南部軍集団が単独指揮│
 │ ・指揮摩擦ゼロ        │  ┌───────────────┐  │ ・指揮摩擦ゼロ        │
 │ ・特化ドクトリン最大  │  │ 共同管理領域  │  │ ・特化ドクトリン最大  │
 │                       │  │ (Joint Sector)│  │                       │
 │                       │──► 相互火力支援  ◄──│                       │
 │                       │  │ 補給ハブ共用  │  │                       │
 │                       │  │ 境界哨戒連携  │  │                       │
 └───────────────────────┘  └───────────────┘  └───────────────────────┘
```

### 3.1 専念領域（Dedicated Sector）

- **指揮権**: 指定された単一の方面軍・軍集団が100%排他的に統率。
- **特徴**:
  - 指揮混線や管轄争い（セクショナリズム）のペナルティが皆無。
  - 方面軍の調達・作戦ドクトリンが純粋に発揮される。
  - 万が一の敵突破時に隣接方面からの自動救援は原則として行われない（手動要請または境界侵犯が必要）。

### 3.2 共同管理領域（Joint Overlapping Sector）

2つ以上の方面軍（または同盟軍）の担当境界が重なり合うバッファ地帯。

- **(1) 相互火力支援（Cross-Theater Fire Support）**:
  - サブタイル戦術マップまたは自動解決において、共同管理領域内の戦闘には**両方面軍の後方長距離砲兵・ミサイル部隊・航空支援が合算**して参戦可能。
  - 敵の大規模攻勢に対し、片方の方面軍だけでは耐えられない場合でも、隣接方面の支援砲火によって撃退できる。
- **(2) 補給ハブ・兵站インフラの共同利用**:
  - 共同管理領域に設置された補給デポや鉄道・パイプライン結節点は、両方面軍の部隊へ同時に物資を供給可能。
  - 片方の兵站線が遮断されても、もう一方の補給網から物資を迂回供給できる。
- **(3) 指揮摩擦・調整オーバーヘッド（Friction Factor）**:
  - 共同管理領域に両方面軍の部隊が密集しすぎると、**「指揮混線（Command Congestion）」**が発生。
  - 通信プロトコルや優先目標の擦り合わせにより、部隊の反応速度に微小なディレイが生じる。司令部HQの「調整能力（Coordination Skill）」やC4I技術が高いほど摩擦はゼロに近づく。

## 4. 自動指揮・占領統治への統合

### 4.1 方面レベルでの「自動侵攻・包囲アルゴリズム」

軍集団に「対A国 A侵攻軍集団」としてターゲット国家・都市群を指定すると、司令部AIは以下の手順を自律実行する：

1. **偵察・チョークポイント特定**: 偵察小隊を前進させ、敵の兵力配置とインフラ線をスキャン。
2. **前哨基地（FOB）の段階前進**: [concept_tile_progression_system.md](./concept_tile_progression_system.md) のTier 1仮設前哨を補給限界地点に自動設営。
3. **包囲孤立化（Encircling）**: 敵中枢タイルを正面から強襲する前に、補給パイプライン・電力を供給している周辺タイルを分断・制圧。
4. **占領軍集団への治安管轄移譲**: 突破部隊は敵主力を追撃して前進し、後方に取り残された都市・採掘タイルの軍政・警備は後続の「D占領軍集団」へ自動で管轄移管される。

### 4.2 タイル過密（みちみち大混戦）の自動回避

[concept_tile_progression_system.md](./concept_tile_progression_system.md) では「1タイル1戦闘団」が原則であり、平時に部隊が重なると移動不能・自壊リスクが生じる。

- 方面軍AIは、前進ルート上のタイル容量（Cap）を先読み計算し、**「進撃路のスタック渋滞」が発生しないよう、行軍速度や迂回路を自動調停**する。

## 5. 同盟統合軍の連携（Combined Joint Task Force）

[concept_alliance_system.md](./concept_alliance_system.md) で定義された「3大思想ベースの不可逆同盟ブロック」において、方面システムは国家の枠を超えて拡張される。

```text
┌────────────────────────────────────────────────────────────────────────┐
│             同盟連合統合司令部 (Combined Joint Task Force)             │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
           ┌────────────────────────┴────────────────────────┐
           ▼                                                 ▼
┌─────────────────────────────────────┐   ┌─────────────────────────────────────┐
│    自国 方面軍 (Nation A HQ)        │   │    同盟国 方面軍 (Nation B HQ)      │
│  - 主力機甲打撃・前線突破を担当     │   │  - 防空網・高度電子戦・兵站を担当   │
└──────────────────┬──────────────────┘   └──────────────────┬──────────────────┘
                   │                                         │
                   └───────────────────┬─────────────────────┘
                                       ▼
                     ┌───────────────────────────────────┐
                     │     同盟共同作戦セクター (Joint)  │
                     │  - C4I標準化によるデータリンク共有│
                     │  - 相互艤装による弾薬・部品の融通 │
                     └───────────────────────────────────┘
```

### 5.1 同盟間での「専念領域」と「共同管理」の分担

- **役割の戦略分業**:
  - 重工業・車体生産に長けた自国軍が「突破侵攻専念セクター」を受け持つ。
  - 電子技術・防空に長けた同盟国軍が「防空・補給線防護専念セクター」を後方に展開。
- **同盟共同管理領域**:
  - 国家間で領土野心が衝突しない（不可逆同盟である）ため、共同管理領域における境界画定摩擦が発生しない。
  - [concept_faction_consensus_and_standardization.md](./concept_faction_consensus_and_standardization.md) に基づき、データリンクが標準化されていれば、同盟国の防空ミサイルが自国戦闘団の頭上を完全援護する。

## 6. エイリアン（集合意識方面集団）が複数国に包囲される力学

エイリアン（原生生態系・集合意識）は全個体が同一の生体ネットワークで結ばれており、人類国家のように内部分裂しない。
しかし地理的には、**「エイリアンの巨大な南部方面集団（巣窟群）が、進出してきた複数国家（A国、B国、自国）によって全方位から包囲される」**という戦略的包囲網（Kesselschlacht）が発生する。

```text
               ┌──────────────────────────────────────────────┐
               │         自国（プレイヤー） 北部方面軍        │
               └──────────────────────┬───────────────────────┘
                                      ▼ (南進)
       ┌────────────────────────┐            ┌────────────────────────┐
       │     A国 東部方面軍     │            │     B国 西部方面軍     │
       │   (Nation A Theater)   │            │   (Nation B Theater)   │
       └───────────┬────────────┘            └────────────┬───────────┘
                   │                                      │
                   ▼ (西進)                               ▼ (東進)
       ════════════════════════════════════════════════════════════════
       │                                                              │
       │         【エイリアン 集合意識 南部方面集団 (巨視的巣窟群)】   │
       │                                                              │
       │  ・全個体同一だが「3方向から同時包囲・圧迫」された状態        │
       │  ・外縁部が各国の前哨基地・焼夷兵器で削り取られる            │
       │  ・【死中求活の暴走】: 最も包囲網の薄い「接合部」へ集中突破  │
       │                                                              │
       ════════════════════════════════════════════════════════════════
                                      ▲ (北進)
               ┌──────────────────────┴───────────────────────┐
               │          C国（または未開拓海嶺・極地）       │
               └──────────────────────────────────────────────┘
```

### 6.1 エイリアン方面集団が包囲された時の動的反応

1. **外縁部の同時圧迫と生体資源の枯渇**:
   - 複数国がそれぞれの方面軍から一斉に巣窟を包囲・空爆・除染することで、エイリアン方面集団の繁殖基盤（養分供給タイル）が外周から順次寸断される。
2. **「継ぎ目（境界）」への死中求活・局所集中突破（Desperate Breakout）**:
   - 包囲された集合意識AIは、均等に反撃するのではなく、**包囲している人間国家間の「共同管理領域」や「国境の隙間（担当部隊が薄い境界線）」**を察知。
   - そこへ数万単位の変異種・大型種を集中突進させ、包囲網を破って特定国家（自国またはA国）の後方領土へ雪崩れ込む。
3. **包囲参加国同士の「共同管理」と「獲物の奪い合い」**:
   - 包囲している複数国が同盟関係にある場合、共同管理領域を通じて**「完全な全周封じ込めと同時殲滅」**が可能。
   - 非同盟または対立国家同士で包囲している場合、「誰がエイリアンの巣窟中枢（希少バイオ資源・コア）を制圧するか」の抜け駆けや、エイリアンが相手国の陣地へ突撃するよう仕向ける謀略（誘導フェロモン弾・退路開放）が交錯する。

## 7. データ構造仕様案 (Rust)

```rust
use serde::{Deserialize, Serialize};
use std::collections::HashSet;

pub type TheaterId = u32;
pub type ArmyGroupId = u32;
pub type TileCoord = (i32, i32);
pub type UnitId = u64;
pub type FactionId = String;

/// 方面軍（Theater Command）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct TheaterCommand {
    pub id: TheaterId,
    pub name: String,
    pub commander_name: String,
    pub faction_id: FactionId,

    /// 専念領域（排他的管轄タイル群）
    pub dedicated_tiles: HashSet<TileCoord>,

    /// 共同管理領域（他方面または同盟と共有するタイル群）
    pub joint_tiles: HashSet<TileCoord>,

    /// 配下の軍集団ツリー
    pub army_groups: Vec<ArmyGroup>,

    /// 方面全体の戦略方針・ドクトリン
    pub doctrine: TheaterDoctrine,

    /// 補給・人員補充の優先度 (1〜5)
    pub supply_priority: u8,
}

/// 軍集団（Army Group / Task Force）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ArmyGroup {
    pub id: ArmyGroupId,
    pub name: String,
    pub role: ArmyGroupRole,

    /// 配属された戦闘団・支援部隊ID
    pub assigned_units: Vec<UnitId>,

    /// 現在の作戦目標（ターゲットタイルまたは敵軍集団）
    pub objective: OperationObjective,

    /// 行動スタンス
    pub posture: OperationalPosture,
}

/// 軍集団の役割特性
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum ArmyGroupRole {
    /// 前線強襲・突破
    AssaultSpearhead { breakthrough_depth: u32 },
    /// 新規制圧地の軍政・治安
    OccupationAndPacification { pacification_priority: bool },
    /// 従来国境の防衛（平時国境警備 ＋ 非常用軍事待機）
    BorderDefense {
        fortified_line: Vec<TileCoord>,
        mobilization_state: bool, // 平時(国境警備隊主導) or 非常時(正規軍展開)
    },
    /// エイリアン包囲・隔離
    XenoContainmentEncirclement { target_nest_core: TileCoord },
    /// 機動予備（危機発生タイルへの緊急即応）
    MobileReserve { reaction_radius: u32 },
}

/// 作戦スタンス
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum OperationalPosture {
    /// 積極的進撃（損耗容認）
    AggressiveAdvance,
    /// 慎重な前進（兵站・防空傘の随伴必須）
    MethodicalAdvance,
    /// 陣地固守（退却厳禁）
    HoldAtAllCosts,
    /// 弾力的遅延（損耗を避けて後退・時間稼ぎ）
    ElasticDelay,
}

/// 共同管理領域における調停データ
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct JointSectorCoordination {
    pub shared_tile: TileCoord,
    pub participating_theaters: Vec<TheaterId>,

    /// 火力支援の相互乗り入れフラグ
    pub fire_support_shared: bool,

    /// 補給ハブの相互開放
    pub logistics_shared: bool,

    /// 指揮摩擦ペナルティ (0.0=円滑, 1.0=完全混乱)
    pub friction_penalty: f32,
}
```
