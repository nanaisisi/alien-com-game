# 産業・モジュールジャンルの相互接続マッピング仕様

本作（4X大戦略＋サブタイル戦術・戦闘団制）における**「産業ジャンル間の類似性・相互接続（サプライチェーン・設備転用・技術シナジー）」**および**「特定ジャンル内モジュールの類似性・マッピングマトリクス」**の仕様設計ドキュメント。

---

## 1. 全体設計コンセプト：「接続性」と「類似性」の分離定義

産業や兵器モジュールを管理する上で、混同しやすい**「接続性（Connectivity / Compatibility）」**と**「類似性（Similarity / Lineage）」**を明確に異なる軸として分離する。

```text
+---------------------------------------------------------------------------------------+
|  【接続性 (Connectivity / Fit)】              │  【類似性 (Similarity / Lineage)】    |
|  - 物理的に「結合・搭載・通信可能か？」       │  - 設計・製造・経験値が「似ているか？」|
|  - サイズ階層（容積・重量）、マウント規格     │  - 同一コア系統、同一半導体、同一加工法|
|  - インターフェース（電源電圧、通信プロトコル)│  - 経験値伝播、生産ライン転用、部品共用|
+---------------------------------------------------------------------------------------+
```

### 1.1 「接続性（Connectivity）」：物理・サイズ・インターフェースの適合性

- **物理・サイズ階層（Form Factor / Size Class）の絶対制約**:
  - 全く大きさの違うモジュール（例: 駆逐艦用の巨大ガスタービンや大開口ソナー）を、物理的に戦闘機や装甲車に「接続」することは不可能。
  - スロット規格・サイズクラス（超小型 S / 中型 M / 大型 L / 超大型 XL）が一致または許容範囲内でなければ接続（搭載）できない。
- **インターフェース整合性**:
  - 給電規格（28V DC / 270V DC / 高圧パルス）、冷却配管接続径、通信データバス規格が適合して初めて「接続」が成立する。

### 1.2 「類似性（Similarity）」：系統・製造・ノウハウの波及度

- **サイズが異なっても類似性は成立する**:
  - 巨大な艦艇用ガスタービン（30MW）と戦闘機用ターボファン（100kN）は、物理的に「接続」はできないが、**「耐熱合金動翼の結晶構造」「燃焼室コーティング技術」**という製造・技術面での類似性は極めて高い。
  - 地上定置型の超大型AESAレーダーと戦闘機の小型ノーズFCSは、物理接続は不可能だが、**「同一規格のGaN素子チップ」「適応ビーム合成アルゴリズム」**において高い類似性を持つ。
- **管理上の役割**:
  - 類似性は「経験値の自動波及（$\Delta Exp$ 伝播）」「製造ラインの転用コスト低減」「共同開発・ライセンス時の研究シナジー」を計算するために用いる。

## 2. 産業ジャンルの定義と類似性マトリクス

産業を8つの標準ジャンルに分類し、相互の類似度（0.0 〜 1.0）を定義する。

### 2.1 産業ジャンル一覧

1. **IND-1: 鉄鋼・先進マテリアル (Materials & Metallurgy)**: 特殊装甲鋼、チタン合金、炭素繊維、人工ダイヤモンド結晶。
2. **IND-2: 重機・構造重工 (Heavy Machinery & Structures)**: プレス加工、車体フレーム、砲塔鋳造、大型油圧機構。
3. **IND-3: 動力・推進機関 (Powerplants & Propulsion)**: ディーゼル、ガスタービン、ジェット推進、核融合炉、伝達系（変速機）。
4. **IND-4: 兵器・火薬・火工品 (Ordnance, Energetics & Pyrotechnics)**: 砲身削り出し、装填機構、弾薬・炸薬、火工品・固形燃料（ロケット推進薬）、ミサイル発射管。
5. **IND-5: 航空宇宙工学 (Aerospace Engineering)**: 航空力学フレーム、軽量化複合材、耐熱構造、高信頼補機。
6. **IND-6: 造船・海洋重工 (Naval & Marine Engineering)**: 艦殻溶接、耐水圧・耐食構造、配管・浮力制御、艦載クレーン。
7. **IND-7: 電子・半導体・センサ (Electronics & Semiconductors)**: GaN/ダイヤモンド素子、基板、AESAアンテナ、熱電冷却。
8. **IND-8: 情報・AIソフトウェア (Software, Cyber & AI)**: FCSアルゴリズム、ECM波形ライブラリ、自律戦闘AI、暗号通信。

## 3. 特定ジャンル内におけるモジュールの類似性マッピング

モジュールジャンル内部では、**「コアブロック（系統）」「スケーリングパラメータ」「インターフェース互換」**によって類似性がマッピングされる。

### 3.1 動力・エンジン（GEN-POWER）内部マッピング

中心となる管理パラメータ: **定格出力（kW / MW）** と **動作サイクル（ディーゼル / ガスタービン / 核融合）**

```text
[共通コアブロック: GT-Series (ガスタービン)]
  ├── GT-800  ( 800 kW) ── [類似度 80%] ──► IFV・装輪戦闘車用 (軽量コンパクト)
  ├── GT-1500 (1,500 kW) ── [基準型: 100%] ──► 主力戦車 (高トルク加減速)
  │                               │ [類似度 85% (コア同一・補機耐塩化)]
  │                               ▼
  │                       GT-1500M (海軍型) ──► 高速ミサイル艇 (洋上連続運転)
  └── GT-3000 (3,000 kW) ── [類似度 65%] ──► 大型輸送ホバー・発電車
```

- **類似性判定ルール**:
  - **同一コア・同一出力**: 共通性 100%（ボルトオン換装可能）。
  - **同一コア・出力差（過給機/気筒増減）**: 類似性 70〜85%（ピストン・動翼・オイル系共通）。
  - **異サイクル（例: ディーゼル vs ガスタービン）**: 類似性 30%以下（燃料フィルタやマウント規格のみ共通）。

### 3.2 センサー・電波・電子戦（GEN-SENSOR）内部マッピング

中心となる管理パラメータ: **素子マテリアル（GaAs / GaN / ダイヤモンド）** と **周波数バンド（X / S / L / ミリ波）**

```text
[共通半導体素子: GaN TR-8 チップ] (Layer 1 マテリアル)
  │
  ├──► [単機能・大開口スケーリング]
  │      ├── Sバンド基地固定面 (12,000素子) ── [素子共通 100% / 装置類似 40%]
  │      └── Sバンド艦載4面板 (各3,200素子) ── [素子共通 100% / 装置類似 50%]
  │
  └──► [多機能統合 (Multi-Function RF)]
         ├── Xバンド戦闘機ノーズFCS (950素子: レーダー/ECM/ESM/通信)
         │     │ [アルゴリズム共有 70%]
         │     ▼
         └── Xバンド艦載射撃指揮イルミネーター (FCS追尾特化)
```

- **類似性判定ルール**:
  - **素子チップ共通**: 半導体製造ライン・調達コスト共通化（Layer 1効果）。
  - **同一周波数帯・専用アルゴリズム**: 追尾・クラッター除去コードの共有（類似性 60%）。
  - **多機能統合型 vs 単能型**: 物理アセンブリとしては非互換だが、電子戦（ECM/ESM）ライブラリデータは100%相互流用可能。

### 3.3 火器・兵装（GEN-WEAPON）内部マッピング

中心となる管理パラメータ: **口径（Caliber mm）** と **装薬/給電方式（火薬 / 電熱化学ETC / レールガン）**

```text
[120mm 電熱化学砲 (ETC) ファミリー]
  ├── 120mm/L44 (戦車砲・標準) ── [基準型: 100%]
  │     ├── 120mm/L55 (長砲身・高初速) ── [類似度 80%: 閉鎖機・給電同一、砲身のみ変更]
  │     └── 120mm 水上無人艇用自動砲塔 ── [類似度 70%: 砲身同一、給弾マガジン無人化]
  │
  └── 120mm 滑腔砲 (通常火薬型) ── [類似度 40%: 砲弾径のみ同一、閉鎖機・FCS非互換]
```

### 3.4 防御・装甲（GEN-ARMOR）内部マッピング

中心となる管理パラメータ: **防護構造（均質圧延 / 複合装甲 / 反応装甲ERA / アクティブ防護APS）**

- **ERA（爆発反応装甲）タイル**:
  - 戦車、歩兵戦闘車、基地トーチカの外壁に同一モジュールブロック（ERA-Box）を敷設（共通性 100%）。
- **複合装甲パッケージ**:
  - プラットフォームの許容重量に合わせ、装甲板の積層ブロック厚みを調整（類似性 75%）。

### 3.5 火工素材（1次）と 固体推進・弾薬アセンブリ（2次生産）

高エネルギー物質は**「Layer 1（1次化学素材: 火薬・推進薬原体）」**と、それを成形・加工して金属筐体や信管と統合する**「Layer 2（2次生産: ロケットモーター / 弾薬アセンブリ）」**に明確に分かれる。

また、2次生産の弾薬製造ラインも一括りではなく、工法・要求設備の違いから**「榴弾」「徹甲弾」「銃弾・小火器弾薬」**の専門ラインに分離される。

```text
【Layer 1: 基礎火工・推進素材 (1次化学生産)】
  ニトロセルロース、過塩素酸塩、RDX/TNT、合成バインダー（共通化学コンビナート）
      │
      ├───────────────────────────────────┐
      ▼                                   ▼
【ロケット・ミサイル推進 (2次生産)】    【弾薬アセンブリ・金属加工 (2次生産)】
  耐熱耐圧ケース・燃焼制御ノズル成形      金属弾殻・侵徹体加工 ＋ 炸薬/発射薬充填
  ├── 固体ロケットモーター                ├── 榴弾 (HE / 大口径鍛造弾殻 ＋ 大量炸薬充填)
  └── 宇宙用固体ブースター                ├── 徹甲弾 (APFSDS / 重金属侵徹体切削 ＋ 高圧薬嚢)
                                          └── 銃弾・機関砲弾 (真鍮/鋼薬莢深絞り ＋ 高速自動組立)
```

- **二次生産ラインの特性と分離**:
  - **ロケット・固体推進モーター**: 耐圧容器（CFRP/耐熱鋼）への真空充填・高温硬化（キュア）が必要。航空宇宙系ラインで生産され、通常の砲弾工場への転用は効かない。
  - **榴弾 (HE / 榴弾砲・爆弾)**: 鋼製弾殻の鍛造・プレス加工と大量の炸薬充填が中心。重工・プレス設備と親和性が高く、量産性が高い。
  - **徹甲弾 (AP / APFSDS)**: タングステンや劣化ウラン等の超高硬度重金属侵徹体の超精密加工・サボ（装弾筒）分離機構が必要。高度な精密冶金ラインを要し、榴弾ラインとは共有できない。
  - **銃弾・機関砲弾 (Small Arms / Autocannon)**: 薬莢の超高速連続深絞りプレスと自動プライマー打込。消費規模が数桁大きく、専用の自動化連続ラインで専属生産される。
- **ゲームシステム・兵站上の挙動**:
  - **1次素材の競合**: 硝酸やニトロセルロース等の原体が枯渇すると、全種類の弾薬・ロケット生産が同時に滞る。
  - **2次ラインの独立性**: 榴弾ラインが余剰でも、専門設備の異なる徹甲弾やロケットモーターの即時増産には転用できない（設備改修や専用ライン構築が必要）。

## 4. データ構造・システム実装イメージ (Rust / データモデル)

ゲーム内部で「接続性（物理・サイズ）」と「類似性（系統・経験値波及）」を管理するための最小データ構造案。

```rust
/// モジュールの物理サイズ区分（接続性の絶対制約）
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub enum SizeClass {
    UltraLight, // 超小型 (歩兵携行、ドローン)
    Light,      // 小型 (軽装甲車、小型航空機)
    Medium,     // 中型 (IFV、戦闘機、対空自走砲)
    Heavy,      // 大型 (主力戦車、大型機、小型艇)
    SuperHeavy, // 超大型 (駆逐艦、大型爆撃機、基地施設)
}

/// 物理スロット・マウント仕様
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct MountInterface {
    pub size_class: SizeClass,
    pub mount_type: String,      // 例: "NATO-STANAG-4694", "Heavy-Ring-1800"
    pub power_bus: String,       // 例: "28V-DC", "270V-DC-HighPulse"
}

/// モジュールの管理仕様
#[derive(Debug, Clone)]
pub struct ModuleSpec {
    pub module_id: String,
    pub genre: ModuleGenre,
    pub mount_interface: MountInterface, // 接続性判定用

    // --- 類似性・系統判定用パラメータ ---
    pub core_family_id: String,          // 同一系統 (例: "GT-Series", "TR-8")
    pub power_output_kw: Option<u32>,    // 出力規模
    pub material_tier: MaterialTier,     // GaAs / GaN / Diamond
    pub software_lineage: Option<String>,// FCSアルゴリズム系統
}

impl ModuleSpec {
    /// 【接続性判定】物理的にスロットへ搭載・接続できるか？
    pub fn can_connect_to(&self, slot: &MountInterface) -> bool {
        // 1. サイズクラスが完全に不一致なら接続不可
        if self.mount_interface.size_class != slot.size_class {
            return false;
        }
        // 2. マウント規格および電源バスの適合
        self.mount_interface.mount_type == slot.mount_type
            && self.mount_interface.power_bus == slot.power_bus
    }

    /// 【類似性判定】設計・製造・経験値の親和度 (0.0 ..= 1.0)
    /// ※ サイズが全く違っても、コア系統や素材が同一であれば高い類似性を持ちうる
    pub fn calculate_similarity(&self, other: &ModuleSpec) -> f32 {
        if self.module_id == other.module_id {
            return 1.0; // 完全同一
        }
        let mut score = 0.0;

        // 同一コア系統からの派生（例: GT-800 と GT-3000）
        if self.core_family_id == other.core_family_id {
            score += 0.50;
        }
        // 素材世代の一致（例: 共にダイヤモンド素子、共に単結晶タービン翼）
        if self.material_tier == other.material_tier {
            score += 0.20;
        }
        // ソフトウェア・アルゴリズム系統の一致
        if self.software_lineage.is_some() && self.software_lineage == other.software_lineage {
            score += 0.20;
        }
        // 物理サイズが同級なら、さらに製造治具の類似ボーナス
        if self.mount_interface.size_class == other.mount_interface.size_class {
            score += 0.10;
        }

        score.min(1.0)
    }
}
```

## 5. ゲームシステム・シミュレーション管理上の役割（バックエンド統括）

本マッピングはグラフィカルなビューアー（閲覧用UI）のためではなく、**「ゲーム内部シミュレーションにおける各種計算の自動化・判定管理インフラ」**として機能する。

### 5.1 調達AI・自動充足の判定基準

- 部隊（戦闘団）が前線で損耗・補充を受ける際、補給幕僚AIは「類似性マトリクス」を参照し、正規部品が欠品している場合に**代替モジュールの互換充足**を自動判定する。
  - 類似度 1.0: 完全互換補充（ペナルティなし）。
  - 類似度 0.7〜0.85: 応急互換補充（現場での調整工数が小幅発生するが、稼働率は維持）。
  - 類似度 0.3以下: 互換不可（部隊は部品待ち状態となり稼働率低下）。

### 5.2 産業転用・生産ライン切替コストの自動計算

- プレイヤーが「主力戦車から歩兵戦闘車へ」「民間トラックから軍用装甲車へ」工場ラインを切り替える際、産業マトリクス（IND-2/3）の接続度合いから**「切替工期（ターン数）」**および**「転用初期不良率」**を算定。
- 近縁ジャンルへの転用は即座に完了し、遠隔ジャンル（造船所から航空機など）への無理な転用は膨大な工期と初期トラブルを課す。

### 5.3 経験値・改修パッチの自動伝播ルーティング

- 1つのモジュール（例: ガスタービンエンジン GT-1500）が実戦で過酷環境データを蓄積した際、トポロジーグラフを辿って**関連モジュール（GT-800、GT-3000、海軍仕様GT-1500M）へ類似度に応じた重み付け経験値 $\Delta Exp \times \text{Similarity}$ をバックグラウンドで自動配信**する。

### 5.4 外交制裁・サプライチェーン断絶の連鎖シミュレーション

- 相手国から特定素材（例: レアアース、GaNウェハー）の輸出禁止を受けた際、産業グラフの依存度エッジを評価し、どのモジュールジャンル（レーダー、精密誘導弾など）が何ターン後に生産不能・稼働率低下に陥るかを自動判定する。

### 5.5 プレイヤー自動化（抽象化）と NPC国家の現実的ジレンマ（世界観フレーバー）

プレイヤーに弾薬工場ごとの口径切り替えや炸薬防爆設備の微細なマイクロマネジメントを強いることはせず、**「プレイヤー国家は幕僚・補給AIによって自動的・いい感じに平準化」**され、**「NPC国家が現実的な産業・兵站ジレンマに苛まれる姿」**を通じて世界観の深み・外交交渉の糸口として還元する。

1. **プレイヤー国家の体験（抽象化・自動最適化）**:
   - プレイヤーは「大まかな優先度（例: 防空重視 / 砲兵弾幕重視）」を指定するのみ。
   - 内部の補給幕僚AIが「1次火工原料」の配分や「各2次ライン（榴弾・徹甲弾・銃弾・ロケット）」の稼働枠を自動調整し、ボトルネックを最小化する。
   - 口径統合の恩恵は「全体的な補給維持費・調達コストの逓減」として自動還元され、煩雑な操作を排除。
2. **NPC国家の挙動・現実的ジレンマ（フレーバー＆外交機会）**:
   - **「多口径工場の立ち上げトラブル」に苦しむ大国**:
     - 新鋭の自動化砲弾工場を建造したものの、多口径フレキシブル化のトラブルで稼働率が上がらず、エイリアン迎撃用の弾薬が不足。「砲弾・原料の緊急融通」をプレイヤーに泣きついてくる（外交・貿易イベントの創出）。
   - **「炸薬ラインの安全事故・能力不足」に悩む小国**:
     - 鍛造弾殻は作れるが炸薬充填プラントが貧弱なNPC国が、プレイヤー国へ「不活性弾殻の輸出」や「火工品・ロケットモーターの完成品調達」を打診してくる。
   - **「前線での弾種不一致（口径乱立）によるNPC軍の機能不全」**:
     - 様々な国から輸入兵器を買い漁ったNPC国家の軍隊が、前線で「105mmと155mmの砲弾補給が混乱して砲兵隊が射撃不能」に陥るなど、AIの弱点・リアリティとして描写される。
